# 0002 按会话隔离本地 agent，用历史指纹判定续接

Status: accepted
Date: 2026-11-25

## 背景

`@cursor/sdk` 的 `agent.send()` 每次接收单条用户消息；在发生工具调用时，单次运行（run）需保持挂起状态，等工具结果回填到同一次运行后才能继续生成后续回复。而 DSH 向适配器发起的每次调用都会传入完整的消息历史加最新消息，期间历史可能因上下文压缩、消息编辑或会话分支（fork）发生变化；此外，会话标题生成、上下文压缩等后台辅助任务也会复用同一个模型提供方。

如果每次请求都新建本地 agent，多步工具调用链路会直接中断，且每轮重发全量上下文开销过大；如果所有会话共用同一个本地 agent，不同会话与后台任务的上下文又会互相串扰。

## 决策

以 `sessionKey` 划分独立会话槽位，每个槽位同一时刻最多允许一个活跃运行：

- 普通主对话使用 `session:<sessionId>`（未提供 `sessionId` 时归入 `session:default`）。
- 带 `purpose` 的后台辅助请求使用 `purpose:<sessionId>:<purpose>`，与主对话完全隔离。

每次收到请求时，通过 `classify(seen, messages, pendingIds)` 比对规范化历史指纹：

- **`fresh`**：首次请求、历史变短、任意前缀消息指纹变化、切换模型或密钥、工具轮次异常收尾或无可续接后缀时，销毁旧实例并新建 agent，将当前完整对话拼成单条用户消息发送。
- **`follow-up`**：历史前缀完全匹配且新增后缀仅含 `user`、`developer` 或 `system` 消息时，复用现有 agent 并只发送新增消息。
- **`tools`**：历史前缀匹配且新增后缀恰好对应当前挂起的全部工具调用结果时，兑现挂起的回调 Promise，让同一次运行继续输出。

当请求被取消、运行报错或插件卸载时，立即销毁对应槽位（取消运行、释放 agent、拒绝所有挂起的工具回调）。

## 影响

- 工具往返在同一次 Cursor 运行内闭环完成；一旦发生上下文压缩或历史改写，指纹比对会自动触发 `fresh` 重建，不会把不一致的上下文硬塞给旧实例。
- 指纹判定严格以正确性优先：助手消息块顺序或文本发生任何改动都会触发 `fresh` 全量重发，带来一定的首字延迟与 Token 开销。
- 同一槽位收到并发请求时直接返回 `INVALID_REQUEST`，不做内部排队，由上层调用方等待或取消。
- 本地 agent 状态通过内存 `LocalAgentStore` 驻留进程内存，不生成 SQLite `sdk-agent-store`；SDK 运行期按 agent 生成的 JSONL 转录目录在释放时按 `agentId` 自动清理，宿主重启或插件重载后自动从 `fresh` 重建，不向 DSH 会话日志写入额外状态。

## 备选方案

- **每次请求都新建 agent**：无法维持工具调用挂起与恢复，且每轮重传完整上下文成本过高，放弃。
- **全局共用单个 agent**：会导致不同会话及后台标题/压缩任务互相污染上下文，放弃。
- **将本地 agent 状态持久化落盘**：需要设计额外的版本化存储并与 DSH 会话生命周期同步，当前场景无跨重启无感续接需求，放弃。
- **仅按 `sessionId` 续接而不校验历史指纹**：在上下文压缩或回退后会造成本地 agent 内部历史与 DSH 视图脱节，放弃。
