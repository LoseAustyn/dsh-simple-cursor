# 0007 普通对话拒绝不支持的调用参数，辅助请求使用默认值

Status: accepted
Date: 2026-11-25

## 背景

Cursor 的本地 Agent 接口不接受 `temperature`、`maxTokens` 与 `stop` 三个采样控制参数，而 DSH 的 `GenerateOptions` 在两类场景下可能携带这些字段：

- 用户在普通对话的 Agent 预设中显式配置了采样温度、最大输出长度或停止词。
- DSH 宿主在发起会话标题生成、上下文压缩、自动评审等后台辅助请求时，会自动附带 `maxTokens`（有时还包含 `temperature` 或 `stop`）。

如果对所有请求一律静默忽略这三项参数，用户在普通对话中设置的采样控制看似生效、实则被丢弃，难以排查；反之，如果对所有携带这些字段的请求一律报错拒绝，DSH 内置的自动生成标题与上下文压缩功能就会直接瘫痪。

## 决策

通过请求上的 `purpose` 字段区分处理：

- **普通主对话（`purpose` 为空或未定义）**：一旦传入 `temperature`、`maxTokens` 或非空 `stop` 数组，`rejectedCallOption()` 立即识别并在 `stream()` 中抛出 `UNSUPPORTED_OPTION`，不发起上游调用。
- **后台辅助请求（`purpose` 非空）**：`rejectedCallOption()` 放行，忽略这些不受支持的控制字段，按 Cursor Agent 默认参数完成调用（空数组 `stop: []` 视为未设置）。

## 影响

- 普通对话中若误配了不受支持的采样参数，用户会收到明确的 `UNSUPPORTED_OPTION` 报错，避免产生配置已生效的错觉。
- 会话标题生成、上下文压缩等宿主内置流程可顺畅运行，代价是这些后台任务携带的 `maxTokens` / `temperature` 限制不会实际作用于 Cursor 侧。
- 后续若新增其他采样控制字段，需明确归入「普通对话拒绝、辅助请求忽略」策略或补充映射测试。

## 备选方案

- **对所有请求静默忽略**：实现最省事，但会掩盖用户在普通对话中的无效配置，放弃。
- **对所有请求一概报错**：会导致自动生成会话标题和上下文压缩不可用，放弃。
- **维护允许放行的 `purpose` 名称白名单**：随着宿主演进新增内部用途，白名单极易滞后漏拦或误伤，直接判断 `purpose` 是否非空更稳妥，放弃。
